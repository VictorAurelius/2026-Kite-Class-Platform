# Security Policy

## Reporting a vulnerability

If you discover a security vulnerability in Kite Platform, **please do not open a public
issue**. Responsible disclosure protects users while a fix is prepared.

Instead, report privately via one of:

- **GitHub Security Advisories** — [open a private advisory](https://github.com/VictorAurelius/2026-Kite-Class-Platform/security/advisories/new)
  (preferred — keeps the report private and trackable).
- **Email** — `vannkite@outlook.com` with subject prefixed `[SECURITY]`.

Please include:

- A description of the vulnerability and its impact.
- Steps to reproduce (proof-of-concept if possible).
- Affected component (KiteHub / KiteClass / shared infra) and version/commit.

## What to expect

- Acknowledgement of your report within a reasonable timeframe.
- An assessment of severity and an estimated fix timeline.
- Credit in the advisory once resolved, if you wish.

## Scope

This is a graduation / soft-launch project. The production stack is gated behind a beta
program and is **not** considered hardened for unrestricted public use yet. Security
findings on the codebase, configuration, and architecture are nonetheless valued.

## Good-faith research

We will not pursue or support legal action against researchers who:

- Make a good-faith effort to avoid privacy violations, data destruction, and service
  disruption.
- Report promptly and give reasonable time to remediate before public disclosure.
- Do not exploit findings beyond what is necessary to demonstrate the issue.
