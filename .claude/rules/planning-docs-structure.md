## 1. Purpose

`documents/03-planning/` is the **active planning area** — where wave plans, implementation strategies, and PR lifecycle logs live. It is NOT an archive (use `documents/07-archived/` for completed/obsolete plans).

## 3. File Placement Rules

### 3.1 Wave plans → `waves/`
Any file that describes work for a specific wave (numbered or named) goes in `waves/`. Naming: `wave-{N|name}-{topic}.md`.

**Examples:**
- ✅ `waves/wave-05-parent-dashboard.md`
- ✅ `waves/wave-saas-data-safety.md`
- ❌ `wave-saas-data-safety.md` (root)

### 3.2 Feature plans → `plans/`
Non-wave plans (one-off improvements, investigations, integrations) go in `plans/`. Naming: `plan-{topic}.md` or `{shortname}-plan.md`.

### 3.3 PR lifecycle logs → `pr-logs/`
Auto-generated by `audit-gate.py` hook. Never hand-edit.

### 3.4 Master PR index → `prs/`
Already well-organized. No changes needed.

### 3.5 Top-level files allowed in `03-planning/`
Only 2 files live at root:
- `README.md` — index + navigation
- `MASTER-GAPS-FIX-PLAN.md` — cross-cutting strategy (changes rarely)

**All other `.md` files must be in a subdirectory.**

## 4. README.md Requirements

`documents/03-planning/README.md` must contain:

1. **Purpose** — 1 paragraph explaining active planning area vs archive
2. **Directory map** — table with path → purpose → typical file count
3. **How to add a new plan** — 3-step process referencing this rule
4. **Links to key docs:**
   - Current roadmap (`roadmap/wave-roadmap-p0.md`)
   - Active wave plan (link to most recent in `waves/`)
   - Rules (this file)
   - Archive policy (link to `07-archived/`)

Auto-update when structure changes.

---

## 5. Archival Rule

A planning doc moves to `documents/07-archived/planning-YYYY/` when:

- ✅ Wave merged AND all gaps in wave marked DONE
- ✅ Plan superseded by newer plan (add `SUPERSEDED_BY: path` to new plan frontmatter)
- ✅ Doc >90 days old AND no recent reference in any PR/commit

Keep in active area until one of above fires. Bulk archival happens end-of-quarter.

---

## 6. Frontmatter Required

Every `.md` in `plans/`, `waves/`, or `roadmap/` must start with YAML frontmatter:

```yaml
---
title: Wave 5 — Parent Dashboard
status: active | complete | superseded | draft
created: 2026-04-18
updated: 2026-04-18
waves: [5]                    # for waves/ files
gaps: [GAP-052]               # for plans touching gaps
superseded_by: plans/foo.md   # optional, if superseded
---
```

**Why:** Enables auto-indexing scripts + history tracking.

Existing files without frontmatter: backfill on next edit, no mass migration required.

---

## 7. Anti-Patterns

| ❌ Don't | ✅ Do |
|---------|------|
| Create new `.md` at `03-planning/` root | Put in `waves/`, `plans/`, or appropriate subdir |
| Duplicate a plan verbatim as "v2" | Edit existing + bump `updated:` in frontmatter |
| Leave plan in `03-planning/` after wave DONE | Archive to `07-archived/planning-YYYY/` |
| Mix wave plans with feature plans | Waves → `waves/`, features → `plans/` |
| Commit without updating README.md when adding subdirs | Keep index in sync |

---

## 8. Enforcement

- **Pre-merge PR review**: reviewer checks new planning docs placed correctly
- **audit-gate.py hook** (future): warn if new `.md` file at root of `03-planning/` not in allowed list
- **Quarterly cleanup**: move stale docs to archive
