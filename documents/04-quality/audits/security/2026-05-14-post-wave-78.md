## Bug List (deliverable — surface before score)

### P0 — BLOCKING v1.0.0-rc promotion

**P0-1: FeedbackController không có rate-limit BE defense-in-depth + tenant context luôn null**
- File: `kitehub/kitehub-subscription/src/main/java/com/kitehub/subscription/feedback/controller/FeedbackController.java:74-79`
- Gateway có rate-limit ở contract docs ghi "10 req/min/IP" nhưng KHÔNG thấy route definition cho `/api/v1/feedback` trong `kitehub-gateway/application.yml` (chỉ có routes cho auth/admin/branding/email/subscription). → Endpoint hiện đi qua catch-all `instance-apis` route forward sang kiteclass-core → SAI service + KHÔNG rate-limit.
- `currentTenantId()` hard-coded `return null;` (line 78) → feedback từ authenticated tenant user không trace được context, mất audit trail; cũng phá vỡ persona-scope analytics.
- **Impact:** spam feedback / abusive content / mass DoS via public endpoint (chỉ honeypot field bảo vệ); audit trail gap cho tenant-scoped abuse reporting.
- **Fix:** add gateway route `id: kitehub-feedback-v1` (priority cao hơn `instance-apis`) với `RequestRateLimiter` 10/min IP-keyed; wire tenantId từ JWT claim `tenantId` (Wave 33+ infra) trong `FeedbackController.currentTenantId()`.

### P1 — Should fix before v1.0.0-rc

**P1-1: SecurityConfig `.anyRequest().permitAll()` default-allow fallback (OWASP A05 + A01)**
- File: `kitehub/kitehub-subscription/src/main/java/com/kitehub/subscription/config/SecurityConfig.java:86`
- Anti-pattern: default-allow thay vì default-deny. Mỗi endpoint mới trong subscription service mặc định public trừ khi explicitly match `/api/v1/admin/**` hoặc `/api/v1/onboarding-progress/**`.
- Wave 78 ship 4 controllers mới (Feedback, BetaStatus, Onboarding, 2FA) → BetaStatus + Feedback đúng ý là public; Onboarding cover bởi `/api/v1/onboarding-progress/**` ✅; 2FA endpoints (`/api/auth/2fa/**`) hiện FALLBACK qua `.anyRequest().permitAll()` — mặc dù controller tự enforce challenge token, default-allow nghĩa là endpoint không có Spring Security guard → nếu controller-level check ever bị refactor wrong, không có defense-in-depth.
- **Fix:** swap to `.anyRequest().authenticated()` + explicit `permitAll()` cho actuator/auth/beta-status/swagger; hoặc thêm `/api/auth/2fa/**` vào authenticated() list.

**P1-2: TOTP encryption key dev-default fallback có thể leak vào production (OWASP A02)**
- File: `kitehub/kitehub-subscription/src/main/java/com/kitehub/subscription/auth/twofactor/TotpSecretCipher.java:40`
- `@Value("${kitehub.auth.totp.encryption-key:dev-key-32-chars-pad-pad-pad-pad-pad}")` — dev-default present in code. Log warn at boot if length < 32, BUT vẫn boot và serve traffic with weak key.
- Nếu production deploy quên set env var → tất cả TOTP secret tại rest sẽ encrypted với key hardcoded → effectively plaintext to anyone who reads source.
- Cipher PostConstruct `validate()` chạy smoke encrypt+decrypt nhưng KHÔNG fail-fast khi key length < 32.
- **Fix:** trong production profile, FAIL-FAST `IllegalStateException` nếu key length < 32 OR matches dev default. Track follow-up gap đẩy lên AWS KMS per `pre-launch-secrets-hardening-checklist.md` §2.4.
- Sister concern: `jwt.challenge-secret` cũng có dev-default `dev-challenge-secret-pad-pad-pad-pad-pad` (`application.yml:97`) — same fail-fast guard cần áp dụng.

**P1-3: Tenant header trust mà không cross-check với JWT claim (OWASP A01)**
- File: `kitehub/kitehub-subscription/src/main/java/com/kitehub/subscription/onboarding/controller/OnboardingProgressController.java:60`
- `X-Tenant-Id` header được trust trực tiếp từ request. Gateway forward, nhưng nếu attacker bypass gateway (vd direct internal call hoặc gateway misconfig) → có thể spoof tenantId.
- Acceptable Phase 1 BETA per gateway trust model docs, NHƯNG không có cross-check với JWT `tenantId` claim → defense-in-depth gap.
- **Fix:** thêm filter compare `X-Tenant-Id` header với JWT claim `tenantId`; mismatch → 403. Hoặc derive tenantId từ JWT exclusively trong protected endpoints.

### P2 — Track for Phase 1.5+

**P2-1: TOTP encryption key chưa wire qua AWS KMS** — per `pre-launch-secrets-hardening-checklist.md` §2.4 acceptable v1 nhưng phải file follow-up. Same concern cho `jwt.challenge-secret`.

**P2-2: SBOM generation chưa wire vào release CI** — per `pre-launch-dependency-hardening-checklist.md` §2.8; manual generation acceptable v1.

**P2-3: Feedback endpoint anonymous + email field optional → spam vector** — DTO validation OK (`@Email`, `@Size(max=320)`), honeypot field present. Risk acceptable nếu fix P0-1 (gateway rate-limit) + content moderation queue (existing). Long-term: ReCAPTCHA cho anonymous submit khi public traffic tăng.
