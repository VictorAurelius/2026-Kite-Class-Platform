## Top 3 Findings

### 1. KiteHub has ZERO custom error pages

**Confirmed:** No `not-found.tsx`, `error.tsx`, `global-error.tsx` in `kitehub/kitehub-frontend/src/app/**`. All 404/500 scenarios (blog-detail unknown slug, invalid instance id, payment id 404, admin id 404) fall back to Next's built-in English defaults. This affects 5+ routes: blog/[slug], instances/[id], admin/instances/[id], billing/payment/[id], and any unknown URL. **H-2 is not just "blog-detail 404" — it is a KiteHub-wide gap.**

### 2. Bulk Import (Wave 1 GAP-051) has NO frontend UI

**Confirmed:** Wave 1 shipped backend endpoints (`POST /api/v1/students/bulk-import/{preview,commit,jobs/{id}/errors}`) but the students list page (`(dashboard)/students/page.tsx`) offers only individual "Thêm học viên" button. No upload button, no dropzone, no job status view, no error report download UI. Users cannot actually use the bulk-import feature — Wave 1 #332 is backend-complete but user-inaccessible.

### 3. Landing hero duplicated-text bug still shipped (K-5 regression)

**Confirmed:** `HeroSection.tsx:26-30` concatenates a hardcoded `<span>Chuyên nghiệp & Hiệu quả</span>` AFTER the dynamic `heroTitle`. When landing data returns `'Quản lý Trung tâm Tiếng Anh Chuyên nghiệp & Hiệu quả'` (page.tsx:45 default), the rendered HTML becomes two lines both containing "Chuyên nghiệp & Hiệu quả". Visible on every landing render without tenant override. Baseline flagged K-5 as P1 and it was not included in #263 empty-states PR — it slipped through.
