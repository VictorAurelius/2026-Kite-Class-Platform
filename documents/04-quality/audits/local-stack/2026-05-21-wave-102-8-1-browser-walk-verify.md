## Findings

### Finding #1 — Gateway service crashed (pre-existing infra gap, blocks item (g) only)

**Symptom:** `kite-gateway` container restart loop với `IllegalStateException: JWT_SECRET (or jwt.secret) is required for kitehub-gateway`.

**Root cause:** `kitehub/docker-compose.kitehub.yml` `kite-gateway:` service block thiếu `JWT_SECRET` env passthrough. Subscription + admin services có `JWT_SECRET: ${JWT_SECRET:?...}` (lines 364, 516); gateway block dừng ở DATABASE_PASSWORD + REDIS_HOST + service URLs — không pass JWT_SECRET (cũng không pass ENCRYPTION_MASTER_KEY).

Application config `kitehub/kitehub-gateway/src/main/resources/application.yml:685` đọc `jwt.secret: ${JWT_SECRET:}` (default empty), `JwtAuthenticationGatewayFilter.java:59` throws khi secret empty.

**Scope assessment:**
- Item (g) "Approve action triggers correct backend" — yêu cầu FE→Gateway→Subscription chain → BLOCKED bởi Finding #1.
- Items (a)→(f) — verifiable via subscription direct (port 8081) + FE direct (port 3001) → NOT BLOCKED.
- GAP-518 AC line "Approve/reject buttons fire correct endpoint" — gap-518 §Acceptance Criteria explicitly marks: "separate scope — not in FE role-guard PR". Item (g) không phải GAP-518 closure criterion.
- GAP-519 AC chỉ yêu cầu sidebar visible + 4 link testid + click navigation (không yêu cầu downstream API call). Verified at code level + chunk level.

**Action:** File GAP-699 follow-up tracking gateway JWT_SECRET passthrough fix (1-2 line compose edit). Wave 102.8.1 ship as scope-adjacent — KHÔNG fix infra trong wave verify-only.

### Finding #2 — Postgres volume password drift (one-off bootstrap workaround applied)

**Symptom:** Spring services (`subscription`, `admin`, `gateway`) failed Flyway init với `FATAL: password authentication failed for user "kitehub"` dù `.env` freshly generated bởi `setup.sh` + compose passes correct env to containers.

**Root cause:** Postgres data volume `kite-platform_kite-postgres-data` từ prior setup cycle retains old kitehub user password. `POSTGRES_PASSWORD` env biến chỉ honored on first init của data dir (Postgres official image behavior). New `.env` generated `bhpXJgImzGWgXuT7tHsV` mismatches stored password.

**Workaround applied:** `ALTER USER kitehub WITH PASSWORD '<current-env>';` via psql local socket (`pg_hba.conf` line 1: `local all all trust`). One-off — KHÔNG ship code edit.

**Future fix consideration:** `setup.sh` could detect volume reuse + offer ALTER USER sync; OR document in runbook (per `local-self-test-before-aws-deploy.md` evidence). Out-of-scope Wave 102.8.1.

### Finding #3 — FE image fresh, no rebuild needed (revises Wave 102.8 Bucket D assumption)

Wave 102.8 Bucket D Log entry for GAP-518/519 stated: "running image `kitehub-frontend:gap-284-test` (retagged `:latest`) was built BEFORE Wave 79+ `(admin)` route group landed". Wave 102.8.1 investigation found `kitehub-frontend:latest` image ID `3f815a433f80` ≠ `gap-284-test` image ID `7bb115c11455`. The `:latest` tag points to FRESH image (built 2026-05-21 04:54 UTC) NOT to stale `gap-284-test`.

Verification: `docker exec kitehub-frontend find ... -name "beta-requests"` confirms `(admin)/admin/beta-requests` route present in current `:latest`. No rebuild required.

**Action:** Skip Step 2 rebuild (task spec). Proceed directly to walk verify with current `:latest`.
