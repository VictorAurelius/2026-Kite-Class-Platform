## Cross-bucket conflicts (META retro)

Two compile-breaking conflicts surfaced AFTER #1727 + #1723 landed and CI re-ran on #1724:

1. **GradeController.java duplicate `@PreAuthorize`** on `initializeGrade()` and `getGradesByClass()` — Bucket E0 (PR #1721) already added the annotations; Bucket E (#1727) re-added them → Java compile error `is not a repeatable annotation type`.
2. **`@Component("authz")` bean collision** — Bucket E (#1727) added `AuthorizationBean` (uses `classes.teacher_id` column, schema-correct); Bucket C (#1723) added `AuthorizationHelper` (uses `TeacherClassRepository` querying non-existent `teacher_classes` table — H2 IT auto-creates but Postgres rejects). Both registered as Spring bean named `"authz"` → `ConflictingBeanDefinitionException`.

**Resolution** (PR #1728): Keep canonical `@PreAuthorize` after `@PostMapping`/`@GetMapping` (file convention); delete `AuthorizationHelper` + `TeacherIdHolder` + their unit test; swap IT bean type to `AuthorizationBean` (compatible `hasAccessToClass(Long)` signature).

**Lesson** (per `pre-mutation-state-check.md` §1.5): pairwise diff across concurrent bucket branches BEFORE merging would have caught both issues. Current process catches POST-merge via next PR's CI failure → 1 inline hotfix cycle. Process improvement candidate for next wave with ≥3 concurrent bucket PRs touching overlapping authz/security packages.
