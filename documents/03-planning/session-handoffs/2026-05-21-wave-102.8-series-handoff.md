## Lessons learned

### Lesson 1 — Concurrent gap-status.csv writes giữa parallel buckets cần rebase resolution

Wave 102.8 Bucket D agent worked off pre-Bucket-B+C main; rebasing against current main produced merge conflict on 3 CSV rows (GAP-694/695/692). Resolution rule applied: **pick freshest value per row** — Bucket C's GAP-694 DONE wins over Bucket D's stale 75%; Bucket D's GAP-695 50% wins over Bucket C's 25%; HEAD's GAP-692 33% kept. Lesson: agents working concurrent gap touches MUST rebase before push OR coordinator rebases at merge time. Codified in memory `feedback_post_merge_doc_sync.md` Wave 102.8 update.

### Lesson 2 — AUDIT_OVERRIDE trailer post-hoc PR body acceptable khi CI failure pre-existing infra grandfathered

PR #1692 Bucket B touched `infrastructure/terraform-aws/variables.tf` (3-line change). `terraform-plan` CI fail OIDC `AssumeRoleWithWebIdentity` (pre-existing infra issue 2 consecutive runs 2 branches). Per `post-wave-audit-mandate.md` §3 override mechanism: nếu mergeable=true (failing check NOT required status), merge OK với `AUDIT_OVERRIDE:` trailer added post-hoc PR body + follow-up gap GAP-698 tracking restoration. Acceptable pattern khi CI failure clearly NOT regression của current PR.

### Lesson 3 — Agent task-kill recovery pattern (coordinator inherits agent's staged work)

Wave 102.8.1 agent `a0dba02f255eccf31` work cực kỳ tốt nhưng bị user kill mid-task do concern "sao agent vẫn đang chạy". Agent đã staged: audit artifact + GAP-699 file + 2 git mv. CSV sync + commit là step tiếp theo bị interrupt. Coordinator recovery pattern:
1. `git status` confirm staged artifact
2. Read agent's audit + gap file để hiểu findings
3. Sync CSV theo intent của audit (GAP-518/519 → DONE, GAP-699 OPEN row append)
4. Commit + push + PR

Pattern reusable cho future agent interruption (user kill / rate limit / token budget hit mid-task). Lesson: agent prompt nên include **heartbeat reporting at key milestones** (vd "Step 3 done, moving to Step 4") để user có visibility tránh kill nhầm.

### Lesson 4 — FE image fresh assumption verify trước rebuild

Wave 102.8 Bucket D Log entry stated FE image `:latest` predates `(admin)` route group → cần rebuild. Wave 102.8.1 investigation revealed `kitehub-frontend:latest` image ID `3f815a433f80` ≠ `gap-284-test` `7bb115c11455`. `:latest` thực ra fresh (built 04:54 UTC today). KHÔNG cần rebuild. Lesson: always verify image age via `docker images --format` BEFORE rebuild action.

### Lesson 5 — Compose env passthrough sync khi ship new code path (audit-to-gap-pipeline §2.7 decision-doc code-sync)

GAP-699 root cause: Wave 89 Bucket A GAP-604 ship `JwtAuthenticationGatewayFilter` reading `jwt.secret: ${JWT_SECRET:}` nhưng compose `kite-gateway:` block không sync env passthrough → gateway crash khi run local. Class incident `audit-to-gap-pipeline.md` §2.7 decision-doc code-sync miss — code decision lands but compose/manifest/runbook không sync same PR. Future fix: PR template checkbox cho code/compose paired sync khi touching `application.yml` env var references.
